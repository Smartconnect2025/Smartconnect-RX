PROMPT: Implement Secure Password Reset Email Flow

I need you to build a password reset (forgot password) email flow that does NOT use Supabase's built-in email sending. Instead, we send the reset email ourselves through our app's SendGrid API. This is critical because Supabase's default flow uses one-time verification links that get consumed by corporate email scanners before users can click them.

How it works:

User enters their email on the forgot-password page
The frontend calls our own API route /api/auth/send-reset-email with the email
The API route uses supabase.auth.admin.generateLink({ type: "recovery", email }) to generate a recovery token WITHOUT sending an email
From the response, extract linkData.properties.hashed_token
Build a link to our own landing page: https://[SITE_URL]/auth/confirm?token_hash=[hashed_token]&type=recovery
Send a branded HTML email through SendGrid with that link
When the user clicks the link, they land on /auth/confirm — a page that shows a "Reset My Password" button
When the user clicks the button, the page calls supabase.auth.verifyOtp({ token_hash, type: "recovery" }) which establishes a session
On success, redirect to /auth/reset-password where the user enters their new password
The reset-password page calls supabase.auth.updateUser({ password }) to save the new password
Why this approach:

Email scanners (Microsoft Safe Links, Proofpoint, Gmail) follow links in emails automatically. With Supabase's default flow, they consume the one-time token before the user clicks it, causing "Reset Link Invalid" errors
Our landing page is scanner-safe: scanners load the page but don't click buttons
The token is only consumed when the user deliberately clicks "Reset My Password"
The email goes through our authenticated SendGrid, so no Gmail "dangerous email" warnings
The email uses our branded template matching the rest of the app
Files to create:

app/api/auth/send-reset-email/route.ts — API route that generates the Supabase recovery token and sends the branded email via SendGrid (@sendgrid/mail). Use createAdminClient() for the Supabase admin call. Always return { success: true } regardless of whether the email exists (security best practice). Use the same email template style as the MFA verification code emails (logo, blue gradient header, security notice footer).

app/auth/confirm/page.tsx — Client-side page that reads token_hash and type from URL search params. Shows a "Reset My Password" button. On click, calls supabase.auth.verifyOtp({ token_hash, type }). On success, redirects to /auth/reset-password. On error, shows "Link Expired" with a link to request a new one. Wrap in <Suspense> since it uses useSearchParams().

app/auth/forgot-password/page.tsx — Update to call fetch("/api/auth/send-reset-email", { method: "POST", body: JSON.stringify({ email }) }) instead of supabase.auth.resetPasswordForEmail().

app/auth/reset-password/page.tsx — Should check for an existing session on mount via supabase.auth.getSession(). If a session exists, show the password form. If not, show an error. The session will already be established by the confirm page's verifyOtp call.

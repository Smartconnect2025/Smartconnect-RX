Complete Payment & Delivery System Blueprint
1. THE 4-STEP PRESCRIPTION WIZARD
Step 1: Select Patient

Search existing patients or create new one
Patient fields: first name, last name, email, phone, DOB, address
Progress bar shows: Patient → Medication → Review → Collect Payment
On completion: redirects to /step2?patientId=xxx
Step 2: Select Medication

Search medication catalog from database
Select medication, dosage, quantity, refills, SIG (instructions)
Set patient price (what patient pays), profit cents (provider markup), shipping fee
On completion: redirects to /step3?patientId=xxx&medicationId=xxx
Step 3: Review & Create

Shows summary of patient info, medication, pricing
Provider reviews everything before submitting
On submit: creates prescription record in database with status pending_payment
Does NOT submit to pharmacy yet — payment must be collected first
On completion: redirects to /step4?prescriptionId=xxx
Step 4: Collect Payment

Shows prescription summary (patient, medication, total cost)

Warning banner: "Payment required before pharmacy submission"

Three payment option cards:

Option A — Send Payment Link (Recommended)

Opens BillPatientModal with "send-link" tab
Calls /api/provider/billing/payment-link to generate a secure Authorize.net payment link
Emails the link to the patient via SendGrid
Patient pays online at their convenience
Prescription status stays pending_payment until patient pays
Webhook from Authorize.net updates status when paid
Option B — Charge Patient Now

Opens BillPatientModal with "charge-now" tab
Uses Authorize.net Accept.js SDK for PCI-compliant card collection
Provider enters card number, expiration, CVV, ZIP
Calls /api/payments/charge-nonce with the payment nonce
Charges immediately, updates status to payment_received
Auto-submits to pharmacy on successful charge
onPaymentSuccess callback fires ONLY on charge success (not on payment link)
Option C — Mark as Paid

For cash, Venmo, Zelle, or external payments
One click — calls /api/prescriptions/[id]/mark-paid
Creates payment transaction with card_type: "manual-payment"
Updates prescription to payment_received
Auto-submits to pharmacy
"Skip for now" link at bottom — leaves prescription as pending_payment

After successful payment: shows success animation, redirects to prescriptions list in 2 seconds

2. PAYMENT INFRASTRUCTURE
Authorize.net Integration:

Accept.js SDK loaded in browser for PCI compliance (card data never touches your server)
Payment nonce generated client-side, sent to your API
Server-side charge via Authorize.net API using the nonce
Payment links generated with hosted payment page
Webhook endpoint (/api/webhooks/authnet) receives payment notifications
Payment Transaction Database Fields:

prescription_id — links to the prescription
payment_status — pending, completed, failed
order_progress — payment_received, submitted_to_pharmacy, etc.
total_amount_cents — stored in cents
medication_cost_cents — drug cost in cents
consultation_fee_cents — provider profit in cents
shipping_fee_cents — shipping cost in cents
card_type — visa, mastercard, manual-payment, etc.
payment_token — unique token for the transaction
paid_at — timestamp of payment
Price Storage Convention:

patient_price in prescriptions table = stored as dollars (e.g., 120 = $120)
profit_cents, shipping_fee_cents = stored as cents (e.g., 4000 = $40)
Frontend multiplies patient_price × 100 to get cents for API calls
3. EMAIL SYSTEM (SendGrid)
Emails sent automatically:

Payment link email to patient (with secure Authorize.net hosted page URL)
Payment confirmation email after successful charge
Prescription submitted to pharmacy notification
Email template pattern:

HTML email with branded header
Clear call-to-action button
Patient name, medication, and amount personalized
4. SHIPPING & DELIVERY (EasyPost)
Integration:

EasyPost API for shipping label generation
Supports USPS, UPS, FedEx through one API
Rate shopping — automatically selects cheapest/fastest option
Flow:

After pharmacy fills the prescription
Admin generates shipping label from the dashboard
Label with tracking number created
Tracking info stored in database
Patient notified with tracking number
Database fields:

shipping_label_url — link to printable label
tracking_number — carrier tracking number
shipping_carrier — USPS, UPS, FedEx
shipping_status — label_created, in_transit, delivered
5. BILLING MODAL (BillPatientModal)
Props:

prescriptionId — which prescription to bill
patientName, patientEmail, medication — display info
medicationCostCents, profitCents, shippingFeeCents — pricing
paymentStatus — current payment state
initialPaymentMethod — "send-link" or "charge-now" (pre-selects tab)
onPaymentSuccess — callback when charge succeeds (not for payment links)
Features inside the modal:

Two tabs: Send Payment Link / Charge Now
Editable cost breakdown (consultation fee, medication cost, shipping)
Auto-calculated total
Card form with Authorize.net Accept.js
Payment link generation with email delivery
Existing link detection (shows manage options if link already exists)
Double-click protection on submit buttons
6. ADMIN BILLING DASHBOARD
What admins can do:

View all prescriptions with payment status
Generate payment links for any pending prescription
View payment transaction history
See which prescriptions are paid vs pending
Filter and search by patient, provider, status
7. SECURITY RULES
Never use FORCE ROW LEVEL SECURITY — always use createAdminClient for server writes
Payment data handled PCI-compliantly (Accept.js keeps card data off your server)
Ownership validation on all payment endpoints (prescriber_id must match logged-in user)
Idempotency guards on charge and mark-paid endpoints (prevents double charges)
Cookie handling: always cookies.set(name, "", { path: "/", maxAge: 0 }) not cookies.delete()
8. STATUS FLOW
pending_payment → payment_received → submitted_to_pharmacy → picked_up → delivered
Each transition is triggered automatically:

Payment collected → status becomes payment_received
Payment received → auto-submits to pharmacy
Pharmacy confirms → picked_up
Shipped and delivered → delivered

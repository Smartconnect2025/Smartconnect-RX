Incoming Prescriptions & Prescription Detail — Complete Feature Blueprint
Overview
The Incoming Prescriptions page (/admin/prescriptions) is the central admin dashboard for managing all prescription orders. It consists of:

Table View — filterable, searchable list of all prescriptions with visual group highlighting
Prescription Detail Modal — full detail dialog opened by clicking any row, with 8 functional sections

All Valid Statuses (in order of progression)

Effective Status Logic
The displayed status is computed via getEffectiveStatus():

IF status === "submitted" AND (no queue_id or queue_id === "N/A"):
  IF payment_status === "paid" → display "payment_received"
  ELSE → display "pending_payment"
ELSE:
  display actual status

This is because prescriptions start as "submitted" in the DB when the provider creates them, but from the admin perspective, if no queue_id exists, it hasn't been sent to the pharmacy yet — so it's either awaiting payment or payment was received.

PART 3: API ENDPOINTS
1. GET /api/admin/prescriptions — Load All Prescriptions
Auth: Admin or super_admin only Pharmacy scoping: If the logged-in admin is linked to a pharmacy via pharmacy_admins, they only see that pharmacy's prescriptions.

Query joins:

prescriptions
  JOIN patients (first_name, last_name, email, physical_address)
  JOIN pharmacies (name, primary_color)
  JOIN payment_transactions (id, payment_token)
WHERE status != 'cancelled'
ORDER BY submitted_at DESC

Group ID lookup: Separate query fetches all order_group_id values to map prescription → group.

Provider lookup: Fetches all providers by user_id in batch, maps prescriber_id → Dr. FirstName LastName.

Test data filtering: Hides patients with last_name in ["harton"] (case-insensitive).

Response shape:

{
  prescriptions: [{
    id: string,
    queueId: string,
    submittedAt: string,
    providerName: string,         // "Dr. Joseph Sughayer"
    patientName: string,          // "Test Test 1"
    patientEmail: string | null,
    medication: string,
    strength: string,             // from dosage column
    quantity: number,
    refills: number,
    sig: string,
    status: string,
    paymentStatus: string,
    patientPrice: number | null,  // dollars
    shippingFeeCents: number | null, // cents
    profitCents: number,          // cents (oversight & monitoring)
    submissionGroupId: string | null, // order_group_id
    trackingNumber: string,
    pharmacyName: string,
    pharmacyColor: string,        // hex color
    carrierStatus: string,        // fedex_status
    estimatedDelivery: string,
    patientId: string,
    hasCustomAddress: boolean,
    customAddress: {street, city, state, zipCode, country} | null,
    patientAddress: {street, city, state, zipCode, country} | null,
    paymentToken: string | null,
    paymentTransactionId: string | null,
  }]
}

2. POST /api/payments/generate-link — Create Payment Link
Auth: Provider, admin, super_admin, or internal API key Input:

{
  "prescriptionIds": ["uuid1", "uuid2"],  // supports single or multiple
  "consultationFeeCents": 100,            // oversight/monitoring in cents
  "medicationCostCents": 9000,            // total medication cost in cents
  "shippingFeeCents": 2500,               // shipping in cents
  "description": "Payment for 2 medications: Dihexa, BPC-157",
  "patientEmail": "patient@email.com",
  "sendEmail": true
}

Behavior:

Checks for existing unpaid payment link for these prescriptions (reuses if found)
Generates unique payment_token (crypto random hex)
Creates payment_transactions record
Links all prescription IDs to the transaction via payment_transaction_id and order_group_id
If sendEmail: true, calls /api/payments/send-payment-email to email patient
Patient total = medicationCostCents + shippingFeeCents + consultationFeeCents
Race condition protection: Uses optimistic locking — sets status to generating_link first, reverts on failure.

3. POST /api/prescriptions/[id]/mark-paid — Mark as Paid (Manual)
Auth: Admin/super_admin or the prescribing provider What it does (in order):

Validates prescription exists and is in pending_payment status
Calculates group total: if order_group_id exists, sums ALL group members' patient_price + shipping_fee_cents + profit_cents
Creates or updates payment_transactions record with card_type: "manual-payment"
Updates ALL prescriptions in the group to payment_status: "paid", status: "payment_received"
Sends confirmation email (async, fire-and-forget) with all medications listed
Submits ALL prescriptions to pharmacy (loops through each, calls submit-to-pharmacy)
Returns success with any pharmacy submission errors as warnings
Key: One mark-paid action processes the ENTIRE group — all items get paid, emailed, and submitted.

4. POST /api/prescriptions/[id]/submit-to-pharmacy — Submit to DigitalRx
Auth: Provider (own Rx only), admin, super_admin, or internal secret header Race condition protection: Uses submitting_to_pharmacy intermediate status — claims the row first, reverts on failure.

DigitalRx API payload:

{
  "StoreID": "from pharmacy_backends",
  "VendorName": "from env NEXT_PUBLIC_VENDOR_NAME",
  "Patient": {
    "FirstName": "", "LastName": "",
    "DOB": "YYYY-MM-DD",           // MUST be this format
    "Sex": "M/F/U",
    "PatientStreet": "", "PatientCity": "", "PatientState": "", "PatientZip": "",
    "PatientPhone": "10 digits only",
    "Email": ""
  },
  "Doctor": {
    "DoctorFirstName": "", "DoctorLastName": "",
    "DoctorNpi": "", "DoctorDea": "",
    "DoctorStreet": "", "DoctorCity": "", "DoctorState": "", "DoctorZip": "",
    "DoctorPhone": "10 digits only"
  },
  "RxClaim": {
    "DrugName": "AIM-{medication}",   // Always prefixed with "AIM-"
    "Qty": "string",
    "DateWritten": "YYYY-MM-DD",
    "RequestedBy": "FirstName LastName",
    "Refills": "string",
    "DrugNDC": "from pharmacy_medications",
    "Instructions": "SIG or default from catalog",
    "Notes": "",
    "Daw": "Y/N"
  },
  "DocSignature": "URL to provider signature image",
  "PDFFile": "base64 encoded PDF or null"
}

Address resolution: Uses custom_address if has_custom_address=true AND has actual data, otherwise falls back to patient's physical_address.

API key handling: Supports encrypted keys — checks isEncrypted(), decrypts if needed.

Critical validation (blocks submission): StoreID, Patient FirstName/LastName, DrugName Optional validation (warns but submits anyway): DOB, address fields, NPI

On success: Updates prescription with queue_id, status: "submitted", submitted_to_pharmacy_at, calculates next_refill_date. Logs to system_logs.

5. PATCH /api/prescriptions/[id]/admin-override — Manual Status/Tracking Override
Auth: Admin or super_admin only Input:

{
  "status": "shipped",              // optional
  "trackingNumber": "870226650547", // optional
  "note": "Confirmed by Leyla"      // optional
}

Valid statuses: pending_payment, payment_received, submitted, packed, approved, picked_up, shipped, delivered, ready_for_pickup, cancelled

What it does:

Updates prescription status and/or tracking number
Logs to system_logs with action ADMIN_PRESCRIPTION_OVERRIDE, recording old → new values
If BOTH status AND tracking number changed: sends patient status notification email via /api/payments/send-status-email
Status → email statusType mapping:

packed/approved → pharmacy_processing
picked_up/shipped → shipped
delivered → delivered
ready_for_pickup → ready_for_pickup
6. PATCH /api/prescriptions/[id]/update-address — Update Shipping Address
Auth: Provider (own Rx only) or admin Input:

{
  "address": { "street": "...", "city": "...", "state": "...", "zipCode": "...", "country": "US" },
  "saveToPatient": true  // also update patient.physical_address
}

What it does:

Sets has_custom_address: true, saves custom_address JSON
If saveToPatient: true, also updates patients.physical_address
Builds recipient list: env PHARMACY_NOTIFICATION_EMAILS + pharmacy's contact_email + pharmacy's notification_emails
Sends styled HTML email to all recipients showing old vs new address
Logs to system_logs with event_type address_update_notification
7. POST /api/prescriptions/sync-tracking — On-Demand Tracking Sync
Auth: Provider (own Rx only) or admin Input: { "prescriptionId": "uuid" } Called automatically when admin opens a prescription detail that has a tracking number and isn't delivered yet. Uses: EasyPost API via fetchAndApplyTracking() shared utility. Updates: fedex_status, estimated_delivery, potentially status if carrier confirms delivery.

8. POST /api/prescriptions/[id]/check-status — Check Pharmacy Status
Auth: Admin only Returns: Current prescription status + last webhook log from system_logs. Note: DigitalRx polling is disabled — status updates come via webhook only.

9. GET /api/prescriptions/submission-groups — Get All Group Mappings
Auth: Any authenticated user Returns: { groups: { [prescriptionId]: order_group_id } }

PART 7: KEY BUSINESS RULES
Group Payment Rule
When generating a payment link or marking as paid for a grouped prescription:

ALL unpaid items in the group are included in one payment
Total = SUM of all (patient_price + shipping_fee_cents + profit_cents) across the group
One payment link covers all items
One mark-paid action processes all items
One confirmation email lists ALL medications
Price Calculation (CRITICAL)
Patient sees and pays:

Total = Σ(patient_price) + Σ(shipping_fee_cents/100) + Σ(profit_cents/100)

patient_price = medication cost in dollars
shipping_fee_cents = shipping in cents
profit_cents = "Oversight & Monitoring" fee in cents (NOT profit — this IS a patient-facing charge)
Submit to Pharmacy Flow
mark-paid → FOR EACH rx in group:
  1. Set status = "payment_received", payment_status = "paid"
  2. Create/update payment_transaction
  3. Submit to DigitalRx API
  4. Set status = "submitted", save queue_id
  5. Send confirmation email (once, listing ALL medications)

DOB Format
MUST be YYYY-MM-DD for DigitalRx API. Never use MM/DD/YYYY.

Phone Format
Strip to 10 digits only. No area code blocking. Function: formatPhoneForDigitalRx().

Drug Name Prefix
All medications sent to DigitalRx get prefixed with "AIM-" if not already.

API Key Encryption
Pharmacy API keys may be encrypted. The system checks isEncrypted() and decrypts via decryptApiKey() if needed.

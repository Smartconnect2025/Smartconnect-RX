Complete Payment & Pharmacy Submission Blueprint
Overview
This blueprint covers the entire payment ecosystem — all ways a prescription can get paid and submitted to pharmacy. There are 4 payment methods, and they all converge on the same pharmacy submission endpoint.

The 4 Payment Methods
#	Method	Who Initiates	Card Entry	Where
1	Send Payment Link	Admin/Provider sends email	Patient enters card on Authorize.Net hosted page	Patient's browser → AuthNet hosted page
2	Charge Now (Pay on Site)	Provider types card into portal	Provider enters patient's card in BillPatientModal	Provider's browser → Accept.js → charge-nonce API
3	Mark as Paid	Admin clicks button	No card — manual/cash/external payment	Admin portal → mark-paid API
4	Webhook (Auto)	Authorize.Net notifies server	Already charged via method 1 or 2	AuthNet server → webhook API
How They All Connect
METHOD 1: Send Payment Link
  Admin → generate-link → email to patient → patient opens /payment/{token}
    → get-hosted-token → AuthNet hosted page → patient pays
    → AuthNet webhook → webhook/authnet/route.ts
    → OR patient returns to /payment/success/{token} → verify-and-complete
    → mark all group Rx as paid → auto-submit ALL to pharmacy
METHOD 2: Charge Now (Pay on Site)
  Provider → BillPatientModal "Charge Now" tab
    → generate-link (sendEmail=false, creates transaction only)
    → Accept.js tokenizes card in browser
    → charge-nonce API charges via AuthNet server-to-server
    → mark all group Rx as paid → auto-submit ALL to pharmacy
METHOD 3: Mark as Paid (Manual)
  Admin → clicks "Mark as Paid" button
    → mark-paid API
    → creates/updates payment_transactions
    → mark all group Rx as paid → auto-submit ALL to pharmacy
METHOD 4: Webhook (Redundant Safety Net)
  AuthNet → POST /api/webhooks/authnet
    → finds matching payment_transactions by authnet_transaction_id or invoiceNumber
    → mark all group Rx as paid → auto-submit ALL to pharmacy
    → retries any failed pharmacy submissions

All 4 Methods Share These Post-Payment Steps:
Update ALL group prescriptions: payment_status="paid", status="payment_received"
Send confirmation email with ALL medications listed
Auto-submit EACH prescription to pharmacy via submit-to-pharmacy
Log results to system_logs
PART 1: FLOW DIAGRAM
Admin clicks "Send Payment Link"
  └→ POST /api/payments/generate-link
      ├→ Creates payment_transactions record
      ├→ Generates payment URL: {siteUrl}/payment/{token}
      ├→ Links all group prescriptions to transaction
      └→ Emails patient via /api/payments/send-payment-email
Patient pays online  OR  Admin clicks "Mark as Paid"
  └→ POST /api/prescriptions/[id]/mark-paid
      ├→ Calculates group total (sum of all medication + shipping + oversight)
      ├→ Creates/updates payment_transactions
      ├→ Updates ALL group members: payment_status="paid", status="payment_received"
      ├→ Sends confirmation email (async, lists ALL medications)
      └→ FOR EACH group member:
          └→ POST /api/prescriptions/[id]/submit-to-pharmacy
              ├→ Race condition: claims with status="submitting_to_pharmacy"
              ├→ Builds DigitalRx payload (AIM- prefix, formatted phone/DOB)
              ├→ Sends to DigitalRx API
              ├→ Saves queue_id, status="submitted"
              └→ Reverts to "payment_received" on failure

PART 2E: VERIFY AND COMPLETE (Payment Recovery)
Route: POST /api/payments/verify-and-complete
File: app/api/payments/verify-and-complete/route.ts (563 lines)
Purpose
Searches Authorize.Net for a matching transaction when:

Patient returns from hosted payment page
Charge-nonce timed out and returned requiresVerification: true
Need to verify if a payment actually went through
Auth: NONE (token-based — payment_token in body)
Logic Flow
If Already Completed:
Checks if any linked prescriptions are missing queue_id (failed pharmacy submission). If so, retries pharmacy submission for those.

If Not Completed:
Claim transaction (payment_status → "processing")
Search AuthNet for matching transaction by authnet_ref_id (invoice number):
First search unsettled transactions (recent, not yet batched)
Then search settled batches (last 30 days)
Validate amount matches (within $0.01)
Update payment_transactions with authnet_transaction_id, card info, paid_at
Update ALL group prescriptions as paid
Auto-submit ALL to pharmacy
Send confirmation email
AuthNet Search Strategy
Step 1: getUnsettledTransactionListRequest → search by invoiceNumber
Step 2: getSettledBatchListRequest (last 30 days) → for each batch:
          getTransactionListRequest → search by invoiceNumber

Find matching payment_transactions by:
authnet_transaction_id (exact match)
invoiceNumber → authnet_ref_id
refId → authnet_ref_id
If already completed → check for failed pharmacy submissions and retry
Validate amount matches (within $0.01)

net.authorize.payment.capture.created

Same as above but triggered by capture event (separate auth+capture flow)
net.authorize.payment.void.created

Sets payment_status="cancelled" on transaction

Idempotency
If payment is already completed, the webhook handler:

Checks all linked prescriptions for missing queue_id
Retries pharmacy submission for any that failed
This makes the webhook a safety net — if charge-nonce or verify-and-complete already processed the payment, the webhook just retries any failed pharmacy submissions

formatPhoneForDigitalRx(phone)
export function formatPhoneForDigitalRx(phone: string | null | undefined): string {
  if (!phone) return "";
  const digits = phone.replace(/\D/g, "");
  if (digits.length === 11 && digits.startsWith("1")) {
    return digits.slice(1);  // strip leading country code
  }
  if (digits.length === 10) {
    return digits;  // already correct
  }
  return "";  // unexpected length — return empty (don't block)
}

Rules: Strip ALL non-digits. If 11 digits starting with "1", remove the "1". Must be exactly 10 digits. No area code blocking.

formatDobForDigitalRx(dob)
export function formatDobForDigitalRx(dob: string | null | undefined): string {
  if (!dob) return "";
  const match = dob.match(/^(\d{4})-(\d{2})-(\d{2})/);
  if (match) {
    // Validate ranges
    if (month < 1 || month > 12 || day < 1 || day > 31 || year < 1900 || year > 2100) return "";
    return `${match[1]}-${match[2]}-${match[3]}`;  // YYYY-MM-DD
  }
  return "";  // not in expected format
}

Rules: Input must be YYYY-MM-DD. Validates month (1-12), day (1-31), year (1900-2100). Returns YYYY-MM-DD. Never returns MM/DD/YYYY.

PART 10: CRITICAL RULES SUMMARY
AIM- prefix: ALL drug names sent to DigitalRx MUST start with "AIM-"
DOB format: MUST be YYYY-MM-DD — never MM/DD/YYYY
Phone format: Strip to 10 digits only — no formatting, no country code
Group payment: ALL 4 payment methods process ALL items in the group (by order_group_id or payment_transaction_id)
Race condition: generate-link, get-hosted-token, charge-nonce, and submit-to-pharmacy ALL use optimistic locking with intermediate statuses
Total calculation: patient_price + (shipping_fee_cents / 100) + (profit_cents / 100) — server-computed values override client values
Authorization header for DigitalRx: Raw API key, NOT "Bearer {key}"
Auth for internal calls: x-internal-secret for submit-to-pharmacy, x-internal-api-key for email endpoints — these are DIFFERENT env vars
Provider lookup: Uses providers.user_id = prescriptions.prescriber_id (NOT providers.id)
Revert on failure: Always revert intermediate statuses (submitting_to_pharmacy → payment_received, link_generating → pending, processing → pending)
Card data never on server: Accept.js tokenizes in browser → opaque token sent to charge-nonce → AuthNet processes server-side. PCI compliant.
Webhook is a safety net: If payment was already processed by charge-nonce or verify-and-complete, webhook only retries failed pharmacy submissions
Payment link expiry: 7 days from generation. get-hosted-token and verify-and-complete check expiry before proceeding.
AuthNet env: AUTHNET_ENV controls sandbox vs production URLs for all AuthNet interactions
profit_cents = Oversight & Monitoring Fees: This IS charged to patients. UI labels it as "Consultation Fee" or "Oversight & Monitoring Fees"

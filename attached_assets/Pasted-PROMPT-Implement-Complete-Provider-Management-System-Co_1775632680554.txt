UTILITY: Phone Number Formatter
Create core/utils/phone.ts:

export function formatPhoneNumber(value: string): string {
  const digits = value.replace(/\D/g, '');
  if (digits.length === 0) return '';
  const truncated = digits.slice(0, 10);
  if (truncated.length <= 3) return `(${truncated}`;
  if (truncated.length <= 6) return `(${truncated.slice(0, 3)}) ${truncated.slice(3)}`;
  return `(${truncated.slice(0, 3)}) ${truncated.slice(3, 6)}-${truncated.slice(6)}`;
}

API ROUTES TO CREATE
1. app/api/admin/providers/route.ts (GET — list all providers)
Auth check: must be admin or super_admin
Uses admin Supabase client
Fetches all users with role provider from user_roles, then fetches matching records from providers table
Cross-references tiers table to build display strings like "Tier0 (0%)" for each provider's tier_level
Returns { providers: [...], total: number }
Each provider object includes all fields plus computed tier_level display string and tier_code
2. app/api/admin/providers/[id]/route.ts (PATCH — update provider)
Auth check: must be admin or super_admin
Accepts body with fields to update (first_name, last_name, phone_number, company_name)
Company name change logic: When company_name changes:
Look up the old company name first
Update the provider record
If old company existed, call RPC remove_non_owned_patient_mappings({ p_provider_id: id }) to remove old patient mappings
If new company exists, call RPC sync_provider_to_group_patients({ p_provider_id: id }) to sync new company's patients
Both RPCs are non-fatal — log errors but don't fail the request
3. app/api/admin/providers/tier-assignment/route.ts (POST — assign tier)
Auth check: must be admin or super_admin
Body: { providerId, tierCode }
Updates providers.tier_level to the given tierCode
4. app/api/admin/invite-doctor/route.ts (POST — create new provider)
Auth check: must be admin or super_admin
Body: { firstName, lastName, email, phone, password, tierLevel, npiNumber, medicalLicense, licenseState, companyName, physicalAddress, billingAddress }
Required: firstName, lastName, email, password
Company name is required — validate on frontend AND backend
Steps:
supabase.auth.admin.createUser({ email, password, email_confirm: true, user_metadata: { first_name, last_name, role: "provider" } })
Insert into user_roles with role "provider"
Insert into providers with is_active: false
If tierLevel provided, update providers.tier_level
If companyName provided, call RPC sync_provider_to_group_patients({ p_provider_id })
Send welcome email via SendGrid with branded template containing login credentials
Cleanup on failure: If any step fails, delete all previously created records (auth user, user_role, provider)
Detect duplicate email errors from Supabase and return user-friendly message
5. app/api/admin/verify-npi/route.ts (GET — verify NPI against CMS)
Auth check: must be authenticated
Query param: ?npi=1234567890
Validates NPI is exactly 10 digits
Calls CMS NPI Registry API: https://npiregistry.cms.hhs.gov/api/?version=2.1&number={npi}
Returns { valid: true, providerName: "John Smith", message: "NPI is valid and active" } or { valid: false, message: "NPI not found in CMS registry" }
6. app/api/admin/reset-provider-password/route.ts (POST — admin password reset)
Auth check: must be admin or super_admin
Body: { email, newPassword }
Looks up provider by email to get user_id
Calls supabase.auth.admin.updateUserById(userId, { password: newPassword })
7. app/api/admin/delete-provider/route.ts (DELETE — delete provider)
Auth check: must be admin or super_admin
Query param: ?email=provider@example.com
Cascade delete in order:
encounters where provider_id matches
patients where provider_id matches
provider_pharmacy_links where provider_id matches user_id
providers where user_id matches
user_roles where user_id matches
supabase.auth.admin.deleteUser(userId)
Collect non-fatal errors but don't stop the cascade

Company Name Feature (the key UI you're asking about)
The Company Name field appears in both the Invite and Edit modals. It has two modes:

Select mode (default): Shows a dropdown of all existing company names, pulled from current providers. A "Type new" link in the top-right toggles to input mode.

New mode: Shows a text input for typing a new company name. A "Select existing" link toggles back to dropdown mode.

When toggling between modes, the company name value resets to empty.

The company list is fetched when either modal opens — it calls GET /api/admin/providers, extracts unique company_name values, sorts alphabetically, and stores in existingCompanies state.

Below the field, show: "Providers in the same company share patient access" in blue text.

For Invite: Company name is required (marked with *). Form submission validates it's not empty before calling the API.

For Edit: Company name is optional but follows the same select/type-new pattern.

Password Generator
Used in both Invite and Reset Password:

const generatePassword = () => {
  const uppercase = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
  const lowercase = "abcdefghijklmnopqrstuvwxyz";
  const numbers = "0123456789";
  const symbols = "!@#$%^&*";
  const allChars = uppercase + lowercase + numbers + symbols;
  let password = "";
  password += uppercase[Math.floor(Math.random() * uppercase.length)];
  password += lowercase[Math.floor(Math.random() * lowercase.length)];
  password += numbers[Math.floor(Math.random() * numbers.length)];
  password += symbols[Math.floor(Math.random() * symbols.length)];
  for (let i = 4; i < 12; i++) {
    password += allChars[Math.floor(Math.random() * allChars.length)];
  }
  password = password.split("").sort(() => Math.random() - 0.5).join("");
};

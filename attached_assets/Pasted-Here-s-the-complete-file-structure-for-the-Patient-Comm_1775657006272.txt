Here's the complete file structure for the Patient Communications system. Everything you need to clone it:

File Structure
core/
  services/
    email-guard.ts          ← Deduplication & rate limiting
    sms.ts                  ← Twilio SMS sending (payment links, status updates)
app/api/payments/
  send-payment-email/
    route.ts                ← Email #1: "Pay for your prescription" with payment link
  send-confirmation-email/
    route.ts                ← Email #2: "Payment received" receipt
  send-status-email/
    route.ts                ← Email #3: Processing / Shipped / Delivered / Ready for Pickup
app/(features)/admin/
  api-logs/
    page.tsx                ← The admin UI that displays Patient Communications (lines 1024-1170)

How Each File Works
1. core/services/email-guard.ts (72 lines)
Purpose: Prevents duplicate emails and enforces rate limits
Function: checkEmailDedup(recipientEmail, emailType, deduplicationKey, windowMinutes)
Checks: Queries system_logs table for recent identical emails within the time window
Rate caps: 100/hour, 500/day
Returns: { allowed: true/false, reason?: string }
2. core/services/sms.ts (108 lines)
Purpose: Sends SMS via Twilio
Functions:
isSmsConfigured() — checks if Twilio env vars exist
sendSms(to, message) — sends raw SMS
sendPaymentLinkSms(to, name, medication, amount, url, provider) — payment link text
sendStatusSms(to, name, medication, statusType, trackingNumber) — status update text
Phone formatting: Handles 10-digit US numbers, adds +1 prefix
3. send-payment-email/route.ts (351 lines)
Trigger: Called by generate-link route when payment link is created
Auth: x-internal-api-key header check
Input: patientEmail, patientName, providerName, medication, medications[], totalAmount, paymentUrl
Dedup: 30-minute window using payment token as key
Email: Full HTML template with AIM branding, prescription details, CTA button, progress tracker
Also sends: SMS via sendPaymentLinkSms if patient phone is provided
Logs to: system_logs table with action PATIENT_NOTIFICATION_SENT or PATIENT_NOTIFICATION_FAILED
Log format: Payment Request Email | To: email | Medication: name | Amount: $X | Provider: name
4. send-confirmation-email/route.ts (365 lines)
Trigger: Called after successful payment (Authorize.Net webhook or verify-and-complete)
Auth: x-internal-api-key header check
Input: Same as above + transactionId, deliveryMethod, pharmacyName
Dedup: 30-minute window using transaction ID
Email: Green-branded "Payment Confirmed" template with transaction details, next steps based on delivery method
Also sends: SMS confirmation
Log format: Payment Confirmation Email | To: email | Medication: name | Amount: $X | Transaction: id | Provider: name
5. send-status-email/route.ts (451 lines)
Trigger: Called by DigitalRx webhook when pharmacy updates status
Auth: x-internal-api-key header check
Input: patientEmail, patientName, medication, providerName, statusType, trackingNumber?, trackingUrl?, pharmacyName?
4 status types: pharmacy_processing, shipped, delivered, ready_for_pickup
Each type has: Custom subject, heading, header color, message, next steps, and progress steps
Dedup: 60-minute window using prescription ID + status type
Tracking: If shipped, shows tracking number and "Track Package" button with URL
Also sends: SMS status update
Log format: Subject | To: email | Medication: name | Provider: name | Pharmacy: name | Status: type | Tracking: number | Rx: id
6. Admin UI — Patient Communications section (lines 1024-1170 in api-logs/page.tsx)
Data source: Supabase query filtering system_logs where action is one of the 4 notification types
Query: supabase.from("system_logs").select("*").in("action", [4 types]).order("created_at", desc).limit(50)
Parser: parseCommsDetails() splits the pipe-separated details string into key-value pairs
Display per entry:
Green circle + checkmark for sent emails
Blue circle + phone icon for sent SMS
Red circle + X for failures
Entry type (e.g., "Payment Request Email"), status badge ("Delivered"/"Failed")
Timestamp
Metadata row: recipient email/phone, Rx name, provider, pharmacy, tracking, amount
Header badges: Total emails count, SMS count, failed count
Database: system_logs table columns used
Column	Usage
action	PATIENT_NOTIFICATION_SENT, PATIENT_NOTIFICATION_FAILED, PATIENT_SMS_SENT, PATIENT_SMS_FAILED
details	Pipe-separated string: `Type
user_email	Recipient email or phone number
user_name	Patient name
status	success or error
error_message	Error details if failed
created_at	Timestamp
